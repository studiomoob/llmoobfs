How this project is made

MoobFS has one maintainer, a software developer, who works with AI coding assistants. Every change is reviewed and signed off by a human; nothing is merged without the KASAN and lockdep run passing.

Every work session is recorded in a journal: what was asked, what was decided and why, what was tested with which command, what failed, and what is still open. Architecture decisions are kept as numbered ADRs, and a decision that changes is pointed to by its successor, never rewritten. Tests that were not run are never reported as passed; a fix comes with a "negative round" that shows its test failing without it.

We say this up front because the kernel community is discussing how to handle AI-assisted work, and we would rather be judged on the record than on a guess. The journals are that record.

Corrections are welcome: if a journal states something wrong, open an issue and it will get a dated note.
