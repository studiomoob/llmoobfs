Open research topics

Questions this project raises and does not answer yet. Each one comes with what exists to start from. If one interests you or a student, write to us.

Reader-set indexing with security labels

The query answers from a per-directory partition when "everyone who can traverse can read". Mode bits and ACLs support a sufficient condition; security labels (SELinux, Smack) do not fit it yet, so labelled systems fall back to per-result checks (journal 0104). Is there a sound condition that brings labels into the partition?

Security, databases

Ordered traversals in a kernel index

The optimization of journal 0048 moved the short "N most recent" queries ahead of SQLite in that pilot. Long ordered traversals from the real client still lose, at about half the speed of SQLite at 60 000 memories (journal 0068, journal 0088). Which structure improves that measured case within the memory budget?

Data structures, systems

Kernel module or user-space index?

The same queries were measured against a per-domain SQLite index kept by inotify (journal 0092, journal 0094). Under which workloads does each win, and what does consistency cost on each side?

Operating systems, evaluation

Measurement uncertainty in filesystem evaluation

The early SQLite and client comparisons are pilots. The later module comparison uses 40 repetitions, held CPU frequency and confidence intervals (journal 0134, journal 0139, journal 0143). Repeating the SQLite comparisons with that method and reproducing them on other hardware remain open.

Performance evaluation

Benchmarks for agent memory at the storage layer

Agent-memory papers benchmark recall quality; few measure the storage queries a memory system issues. A reproducible workload from real clients would be useful beyond this project.

AI systems, benchmarking

The obligations of a stacked filesystem

Credentials, remount through the new mount API, the lower filesystem's own rules: a stacked filesystem inherits obligations that are scattered across overlayfs's history. A checked list, with tests, would help every stacked filesystem (journal 0099).
