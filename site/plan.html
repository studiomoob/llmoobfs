Plan · Inputs, processing, outputs

Where we are going, one milestone at a time.

An agent writes memories as ordinary files with typed attributes; a native kernel layer validates and indexes them over a mature filesystem; any program reads them back and queries them by attribute. Pick a milestone to see which parts exist at that point.

Green boxes are implemented and tested in an isolated Linux VM (one kernel series; ext4, btrfs and XFS): the frozen M1 experiment, the M2 layer (phases 2a–2e) and the POSIX authorization of QUERY (M3 phase 3b), as recorded in the roadmap. White boxes are proposals from ADR-0005, ADR-0007 and the M3 specification; the M4 pilot is journal 0088, and the tags are source pre-releases, not a production release.

How to read the plan

  • The middle column is where MoobFS exists. Input and output are contracts with the outside world; the project's contribution is what happens inside the kernel between them.
  • Nothing mature is rebuilt. Blocks, journaling, reflink and snapshots come from the lower filesystem; git keeps versioning content. The layer is only the memory-specific part (ADR-0007).
  • M4 closes the loop without kernel code. Semantic retrieval and context assembly stay in the agent application, as decided in ADR-0005.

Free software already covers several steps: dm-log-writes and xfstests for crash testing, virtme-ng for instrumented kernels, Haiku's bfs_shell as a behavioral oracle for queries. See the ecosystem survey.

Status: M1, the M2 layer (phases 2a–2e), M3 phase 3b and the domain-scoped QUERY2 are implemented and tested in a VM on one kernel series, over ext4, btrfs and XFS; the M4 measurements are pilot-grade and the report is journal 0088. The command-line tool, the Python library and the MCP adapter are in place, the mounted gates of G1, G4 and G5 and the recovery drill of G3 passed (ROADMAP). The kernel interface is frozen to fixes and hardening (ADR-0022). The identity convention, a change cursor and a production release remain open. White boxes describe intent, not behavior; each requires a specification, invalid-input tests and an explicit compatibility decision before code. Source pre-release tags exist through v0.4.1-experimental; there is no production release.
