# Developer experience plan on GitHub

Date: 2026-10-11. Status on 2026-10-12: **plan concluded** (section 4); optional pending items and
hand-offs in section 4. Status history: proposal approved by the maintainer; batch 1 concluded (journal
[0032](history/0032-dx-batch1.md)); batch 2 implemented; OpenSSF Best Practices "passing" badge obtained on
2026-10-12; only the Codespaces measurement pending (journal [0039](history/0039-dx-batch2.md)); batch 3
concluded, with the maintainer's actions applied on 2026-10-12 (journal
[0041](history/0041-dx-batch3.md)). Complements [`community-plan.md`](community-plan.md)
(policies, templates, lint CI and DCO) and [`seo-geo-plan.md`](seo-geo-plan.md) (discovery),
which have already been largely executed and are not repeated here.

Goal: make the repository easy to find, to understand in a few minutes and to
contribute to without friction for first-time arrivals, without weakening the cautions of the
experimental stage or the rule that the module only runs in a disposable VM.

## 2. Batches

### Batch 1 — Quick adjustments (this round)

1. Apply `good first issue` together with `difficulty/good-first-issue`, and `help wanted` on the issues
   open to contributors; document the rule in `docs/labels.md`.
2. Turn on secret scanning and push protection; turn on automatic branch deletion after merge.
3. `.github/CODEOWNERS` pointing to the maintainer (automatic review request; does not block,
   since `require_code_owner_reviews` stays off).
4. `CITATION.cff` ("Cite this repository" button).
5. `make help` and `make lint`; the CI `Lint` job now calls `make lint`, so that the local
   command and CI are the same. The SPDX check moves to `scripts/check-spdx.sh`, which
   issue #15 can extend to shell and Python.
6. A welcome discussion in Discussions and three pinned issues.

### Batch 2 — Tooling

- Devcontainer with docker-in-docker and an "Open in Codespaces" button. Before announcing: measure in
  Codespaces the time of `make vm-test`, the disk used and the minimum machine; record the numbers
  or the failure.
- OpenSSF Scorecard (workflow and badge) and enrollment in OpenSSF Best Practices.
- CodeQL for the C tools (`tools/`, `common/`, `bench/`).
- `checkpatch.pl --no-tree` on `layer/` and `kernel/` in the `Lint` job, starting as a warning.
- Path labeler (`area/*`) and a first-contribution message.

## 3. Out of scope

- "Stale" bot: it automatically closes newcomers' issues and does not suit a small project.
- Wiki: the versioned documentation lives in `docs/`.
- Any change to `layer/`, `kernel/` or the format.
