# 0275 — The port to Linux 7.3 (in progress)

Date: started 2026-11-08, 14:35 Brasília time; this round ended 14:50 Brasília time. Status:
**in progress**: the module builds on 7.3.3 and on 6.12.116; nothing has been loaded or run on
7.3. Estimated effort L (ADR-0034); labor time of this round about 15 min of building and
reading on top of the port map of journal 0272.

## Goal

ADR-0034's port to 7.3 (Debian 14's series): adapt `layer/` to the kernel interfaces that changed
between 6.12 and 7.3.3, with no change of behavior, UAPI or on-disk format, and the 6.12 build
as it was. The map of journal 0272 ("Port map to 7.3.3") listed the sites; overlayfs and
`fs/backing-file.c` of 7.3.3 are the model, and `Documentation/filesystems/porting.rst` of 7.3.3
the list of changes. References below are to the 7.3.3 tree unless they say 6.12.116.

## Shape of the port

- `layer/moobl_compat.h` (new) holds the version key and the helpers for calls whose form
  changed; the call sites that change one of the layer's own operations carry an
  `#if MOOBL_VFS_73` branch. The key is `LINUX_VERSION_CODE >= KERNEL_VERSION(7, 3, 0)`. Which
  release between 6.13 and 7.2 introduced each form was not established (only the 6.12.116,
  6.18.62 and 7.3.3 trees are at hand), so releases from 6.13 to 7.2 stop with an `#error`
  naming ADR-0034 instead of a list of type errors; 7.2 is ported when it is a target.
- `static_assert` on the forms whose meaning is in the type: `vfs_mkdir()` (7.3: returns a
  dentry and consumes it on error; 6.12: returns an int and does not) and
  `start_renaming_dentry()`, in the manner of journal 0221 (M8.1).
- `scripts/checkpatch.sh` runs checkpatch on the header separately with `LINUX_VERSION_CODE`
  and `CONSTANT_COMPARISON` ignored, so the version key is allowed there and nowhere else.

## Interfaces whose form changed

| Interface | 6.12 | 7.3.3 | Where |
| --- | --- | --- | --- |
| lower lookups | `lookup_one_len()`, `lookup_one_len_unlocked()` | `lookup_one()`, `lookup_one_unlocked()` with `&nop_mnt_idmap` and `QSTR_LEN()` (porting.rst:1208, 1217) | `moobl_lookup_one*()`; `moobl_lookup`, `moobl_lock_parent`, `scan_child` (index.c) |
| new-inode test | `inode->i_state & I_NEW` | `inode_state_read_once(inode) & I_NEW` (`include/linux/fs.h:878`), as ecryptfs does after `iget5_locked()` | `moobl_inode_is_new()` |
| drop test | `generic_drop_inode()` | `inode_generic_drop()` (`fs.h:2977`), same body | `moobl_generic_drop()` |
| default dentry ops | `sb->s_d_op =` | `set_default_d_op()` (porting.rst:1260, `fs/dcache.c:2101`) | `moobl_set_d_op()` |
| layer's `d_revalidate` | `(dentry, flags)` | `(dir, name, dentry, flags)` (porting.rst:1146) | `moobl_d_revalidate_73()` calls the unchanged function |
| file flags | `struct fileattr` | `struct file_kattr` (`include/linux/fileattr.h:44`), same fields used | `moobl_kattr` |
| `vfs_create` | `(idmap, dir, dentry, mode, excl)` | `(idmap, dentry, mode, delegated_inode)` (`fs/namei.c:4177`) | `moobl_vfs_create()` |
| `vfs_rmdir`, `vfs_symlink` | no delegation argument | `delegated_inode` NULL (`fs.h:1764–1777`), as every overlayfs call (`fs/overlayfs/overlayfs.h:212–281`) | `moobl_vfs_rmdir()`, `moobl_vfs_symlink()` |
| `.create` | with `excl` | without (porting.rst:1409) | `moobl_create_73()` |
| `.mkdir` | returns int | returns a dentry, NULL when the given one was used (porting.rst:1190) | `moobl_mkdir_73()` |
| `struct backing_file_ctx` | `user_file`, `end_write(file, pos, ret)` | no `user_file`, `end_write(kiocb, ret)` (`include/linux/backing-file.h:15–19`) | `MOOBL_CTX`, `moobl_file_end_write()` |
| splice helpers | `loff_t *ppos` | a kiocb of the layer file (`fs/backing-file.c:279`, `299`) | `moobl_splice_read/write`, built as `ovl_splice_read/write()` (`fs/overlayfs/file.c:378–437`) |
| `i_ino` | `unsigned long` | `u64` (`fs.h:782`) | the self-check's warning prints `%llu` |

`excl`: ext4, btrfs and XFS never read it on 6.12.116 (`ext4_create()`, `btrfs_create()`,
`xfs_vn_create()`); only NFS did, so dropping it changes nothing for the supported lowers.
`delegated_inode` NULL: a delegation on the lower directory (nfsd's) is broken without waiting
(`include/linux/filelock.h:539`, `try_break_deleg()`), as `vfs_unlink()` and `vfs_link()`
already did with NULL on 6.12.

`file_remove_privs()` before the write and splice-write helpers is kept: `backing_file_write_iter()`
and `backing_file_splice_write()` call it on the layer file on 7.3.3 (`fs/backing-file.c:266`,
`312`), but they did on 6.12.116 too (`ctx->user_file`, `fs/backing-file.c:225`, `312`), so the
module's own call, under the layer inode's lock, stays as on 6.12 and the second call finds
nothing to remove on both.

## The five sensitive items

1. **`vfs_mkdir()`.** On 7.3.3 it returns the dentry the directory is in and, on any error,
   calls `end_creating(dentry)`, which unlocks the parent and drops the dentry
   (`fs/namei.c:5380–5423`, porting.rst:1318). The 7.3 branch of `moobl_mkdir()` therefore only
   drops the lower write access and the negative upper dentry on error, without
   `moobl_unlock_parent()`; on success it continues with the returned dentry, which
   `moobl_instantiate()` installs, as `ovl_do_mkdir()`'s callers do
   (`fs/overlayfs/overlayfs.h:250–261`, `fs/overlayfs/dir.c:185`).
2. **Rename.** `lock_rename()`/`unlock_rename()` are static in 7.3.3 (`fs/namei.c:3782`, `3834`;
   porting.rst:1375). The 7.3 branch uses `start_renaming_dentry()` (`fs/namei.c:3959–4051`),
   the variant overlayfs uses when it already holds the source dentry
   (`fs/overlayfs/copy_up.c:564`, `fs/overlayfs/super.c:599`; `ovl_rename()` itself looks both
   names up with `start_renaming()`, `fs/overlayfs/dir.c:1270–1327`), and `end_renaming()`
   (`fs/namei.c:4118`). It locks by the source's current parent, refuses with EINVAL a source
   unhashed or moved from `lower_old_dir`, looks up the target under the locks with the
   caller's search permission (`lookup_one_common()`, as `lookup_one_len()` did) and refuses
   the traps. The module's own checks follow unchanged: positivity of the upper and lower
   targets and the identity of the lower inode (ESTALE), the parents and hashing (EINVAL).
   Errno changes, only when the lower changed behind the layer during the call:
   `RENAME_NOREPLACE` onto a lower target that became positive gives EEXIST, and
   `RENAME_EXCHANGE` onto one that became negative gives ENOENT, from
   `lookup_one_qstr_excl()`'s `LOOKUP_EXCL` and missing `LOOKUP_CREATE` (`fs/namei.c:1790–1830`),
   where 6.12 gives ESTALE; an exchange whose lower target is an ancestor of the source gives
   EINVAL, where 6.12 gives ENOTEMPTY; and a source both moved or unhashed and with a stale
   target gives EINVAL before ESTALE. The target lookup passes `LOOKUP_RENAME_TARGET |
   LOOKUP_CREATE` where `lookup_one_len()` passed none; ext4, btrfs and XFS use those flags as
   hints only.
3. **getattr.** `AT_GETATTR_NOSEC` does not exist on 7.3.3; `vfs_getattr()` runs the security
   hook and then `vfs_getattr_nosec()` (`fs/stat.c:254–262`). The 7.3 branch of
   `moobl_lower_getattr()` always calls `vfs_getattr_nosec()` on the lower, as
   `ovl_real_getattr_nosec()` does (`fs/overlayfs/inode.c:162–189`); on 6.12 every call from
   the VFS carried the flag (6.12.116 `fs/stat.c:168`), so this is what every call did there.
   The 6.12 branch is unchanged.
4. **Lookups.** `lookup_noperm*()` skip the parent's search check (porting.rst:1217–1227);
   `lookup_one*()` keep it and are the forms for "accessing a filesystem from outside that
   filesystem" (porting.rst:1208). The layer uses `lookup_one()` and `lookup_one_unlocked()`
   with `nop_mnt_idmap` (the lower is never idmapped, `moobl_fill_super()`).
5. **Lower `d_revalidate`.** It now receives the parent's inode and a name that must stay
   stable during the call (porting.rst:1146). The layer calls it only in ref-walk; the 7.3
   branch of `moobl_lower_d_revalidate()` pins the parent with `dget_parent()` and passes a
   `take_dentry_name_snapshot()` of the lower dentry's name, as the ref-walk branch of
   `ovl_revalidate_real()` (`fs/overlayfs/super.c:83–117`).

**Leases.** `kernel_setlease()` returns EINVAL when `->setlease` is NULL on 7.3.3
(`fs/locks.c:2108–2115`, porting.rst:1338), where 6.12.116 fell back to `generic_setlease()`
(`fs/locks.c:1984–1992`). The regular-file operations set `.setlease = generic_setlease` on 7.3,
as `ovl_file_operations` (`fs/overlayfs/file.c:665`). The directory operations do not, although
overlayfs sets it there too (`fs/overlayfs/readdir.c:1091`): 6.12's `vfs_setlease()` refuses a
directory, and 7.3.3's `fcntl_setlease()` does too, so without it a directory lease stays
refused on 7.3 as on 6.12 (no nfsd directory delegation through the layer).

## Review of the two locking paths against 7.3.3

Read by the coordinator on 2026-11-08 against `fs/namei.c` of 7.3.3.

- `moobl_mkdir()`: on error, `vfs_mkdir()` has already unlocked the parent and dropped the
  dentry, so the 7.3 branch only drops the write access and the negative upper dentry; it does
  not unlock or `dput()` again. On success it continues with the dentry `vfs_mkdir()` returns,
  as `ovl_do_mkdir()` does.
- `moobl_rename()`: `__start_renaming_dentry()` locks with `lock_rename_child()`, refuses an
  unhashed source or one whose parent is not `rd.old_parent`, looks up the target, refuses the
  two traps after dropping the target, and on every error unlocks before it returns; the layer
  then skips `end_renaming()` (`goto out_drop`). On success it takes its own references to the
  source, the target and the source's parent, which `end_renaming()` drops: the layer's own
  reference to the lower source is still dropped once at `out_put`, and `lower_new` is cleared
  so that it is not dropped twice. `rd.old_parent` starts as a borrowed pointer and is replaced
  by the referenced one only on success. The layer's checks after the lookup (`ESTALE` for a
  lower changed behind it, `EINVAL` for a moved or unhashed dentry) still run under the locks;
  the parent and unhashed tests duplicate the helper's and cost nothing.

## KASAN/UBSAN/lockdep on 7.3.3, first run

2026-11-08, 11:00–15:55 BRT (calendar time), test host, `vm/kasan-local.sh` on a copy of commit
`68dbdd6` with `KERNEL_VERSION: 7.3.3` and the 7.3.3 tarball of kernel.org built with
`vm/kasan.config` (`KCACHE` of its own); the console reports `Linux version 7.3.3-virtme`.

- Every step of the suite passed: 271 pass markers (`QUERY2_PASS`, `SELFCHECK_PASS`,
  `PERMCHURN_PASS`, `HOOKRACE_PASS`, `HOOK_RACE_RENAMEOVER_PASS`, `POWER_LOSS_REPLAY_PASS`,
  `MOOBFS_PYLIB_PASS` among them); `LANDLOCK_SKIPPED` and the memcg steps skipped as on 6.12.
- The run still failed with `MOOBFS_VM_FAIL: kernel-diagnostic-layer`: at 2560 s lockdep printed
  `BUG: MAX_LOCKDEP_CHAIN_HLOCKS too low!` and `turning off the locking correctness validator`,
  in `join_transaction()` called from `btrfs_evict_inode()` under `drop_caches`. That is
  lockdep's chain table filling up (`CONFIG_LOCKDEP_CHAINS_BITS=16`, the default;
  `kernel/locking/lockdep_internals.h`), not a locking report. Before it, lockdep reported
  nothing; after it, the last part of the run, about 1,100 s, was not checked for locking.
  KASAN and UBSAN stayed on and reported nothing.
- Fix in the harness, not in the module: `vm/kasan.config` sets `CONFIG_LOCKDEP_CHAINS_BITS=18`
  (the help text of `lib/Kconfig.debug` names this option for that message). The CI kernel
  6.12.112 also gets the larger table; its cache key follows the fragment's hash.

## Native suite on Debian's 7.3.3

On 2026-11-08 Debian's 7.3.3 (`linux-image-7.3.3+deb14-amd64` `7.3.3-1`) is in sid only: forky
(testing) has 7.2.15 and trixie-backports 7.2.12, which the port refuses at build time. The
suite's container takes a base image per kernel (`vm/run.sh`, `MOOB_BASE`: trixie for 6.12, sid
pinned by digest for 7.3.3), because the 7.3 headers need sid's compiler.

Three harness changes were needed; none in `layer/`:

- The M1 module (`kernel/`) does not build on 7.3 (`iomap_read_folio()` and `iomap_readahead()`
  take a third argument, `i_state` became a struct); ADR-0034 covers the layer only. On a 7.x
  kernel `vm/in-container.sh` builds and packs the layer alone, and `vm/init` prints
  `MOOBFS_VM_SKIPPED` instead of running phase 1.
- `crc32c_generic.ko` is `crc32c-cryptoapi.ko` on 7.3.
- The skip marker is the first console line, after the firmware's escape codes, so it now starts
  on a line of its own.

Fourth run, `d0bdd75`, test host, KVM, 2026-11-08 18:10–18:29 BRT (calendar time): exit 0,
`MOOBFS_LAYER_PASS`, `MOOBFS_ACCEPTANCE_PASS`, 299 pass markers, no kernel diagnostic; skipped
only `MOOBFS_VM_SKIPPED` (M1) and `PYLIB_SKIPPED`, which every native run prints. The three
earlier runs stopped at the M1 build, the crc32c name and the marker, in that order.
