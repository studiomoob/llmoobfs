### R2-1 — A directory 65 or more components below the mount root is placed nowhere: its chmod sets no fallback and a value change below it is not indexed

- **Kind:** security (disclosure after a permission change) and defect (stale answers).
- **Severity:** medium. A user who could traverse a domain keeps receiving, without per-result
  checks, the names and attribute matches of files under a directory the owner has since made
  private, and queries keep matching the old value of a changed attribute, until the domain is
  built again. The tree needs 65 directory levels under the mount root, which any user with a
  writable directory can create.
- **Where:** `layer/index.c` `where_is()` 575–607 (`MOOBL_MAX_DEPTH` 64: the walk stops and
  returns false for a dentry with 65 or more components), `place_dentry_above()` 619–623
  (`hetero = true`, `domain = 0` when `where_is` fails), `depth_and_domain()` 696–709,
  `moobl_index_perm_changed()` 2071–2092 (the directory branch sets the fallback only when
  `depth_and_domain` succeeds), `moobl_index_set()` 1820–1823 (`domain_live(0)`: the outside
  part is not built, so the write is not applied), `moobl_rename_crosses_domain()` 2097–2112
  (`EXDEV` when `where_is` fails). The scan has no such limit: `scan_push_dir()` 1246–1293
  inherits `inner` and `inner_ok` at any depth, so the build places these files in their
  domain, and `QUERY2` answers them from the homogeneous partition.
- **Scenario:** domain `d/` (0755) with a chain `a/a/…/a` of 66 directories (0755) and a file
  `f` (0644, `user.moob.kind = x`) at the bottom. uid 1001 runs `QUERY2` on `d` (builds the
  domain; `f` is returned). The owner runs `chmod 0700` on the 65th directory of the chain and
  `setxattr user.moob.kind = y` on `f`. Expected, as in the control with a 10-level chain: the
  chmod of a directory inside the domain puts the domain in fallback mode, `QUERY2` as uid 1001
  returns nothing (the per-result check fails), and `kind == x` matches nothing. Observed: the
  chmod sets no fallback (`where_is` fails for the directory), `QUERY2 kind exists` still
  returns `f` to uid 1001 although `open(f)` gives `EACCES`, `kind == x` still matches `f` and
  `kind == y` matches nothing (the write hook placed `f` outside every domain and found the
  outside part not built). A `mv` of a directory at that depth inside its own parent is refused
  with `EXDEV`.
- **Reproducer:** `tests/review-deep-tree.c` through `tests/review-3627172-vm.sh`. Result lines
  at `3627172`: control `depth=10 chmod_depth=5 … before=1 exists=0 eq_x=0 eq_y=0 open=-1
  errno=13`; defect `depth=66 chmod_depth=65 … before=1 exists=1 eq_x=1 eq_y=0 open=-1
  errno=13` and `depth=70 chmod_depth=0 … exists=1 eq_x=1 eq_y=0 open=0`.
- **Confidence:** reproduced.
- **Note:** the limit itself is a reasonable guard against unbounded walks; the defect is that
  the three write-path users of `where_is` treat "too deep" as "outside every domain" while the
  scan does not. Either the scan should refuse (or classify as heterogeneous) what it finds
  beyond the depth the hooks can place, or a failed placement should mark the domain lost
  (`domain_lost`) or set the fallback, as every other "cannot evaluate" case does.

### R2-2 — A file renamed inside its directory while the scan reads it keeps the scan's listing name; the stale name survives the dirty re-read

- **Kind:** concurrency (the class of round 1: a value computed before the loader registration
  and reused after the retry).
- **Severity:** medium. After the layer inode is evicted, `QUERY2` returns a path that no
  longer exists, and checked queries (fallback, LSM, v1) silently omit the file, until the
  domain is built again or the file is written or renamed once more. No disclosure: the path
  check compares inode numbers.
- **Where:** `layer/index.c` `scan_child()` 1330 (`cpath` from the directory listing),
  `scan_file()` 1295–1306, `index_load()` 1095–1170: registration 1107, the "renamed away" check
  1113 compares only `d_parent`, the dirty retry 1121–1127 keeps the same `path`, the store
  1130–1133 (`index_set_path(ix, rec, path)` on every iteration). `moobl_index_renamed()`
  1973–2047 adopts the file at its new name (`record_dentry_path(where)`), which the scan's
  retry then overwrites because `index_replace()` 1068–1082 frees the adopted record.
- **Scenario:** CPU A (build) lists `D/a`, registers the loader, reads the attributes and
  sleeps (`scan_delay_us`). CPU B renames `D/a` to `D/b` through the layer: the hook marks A's
  loader dirty, finds no record and adopts the file with the name `D/b`. CPU A takes the lock,
  sees `dirty`, re-reads (the dentry is hashed and has the same parent, so neither check at
  1111–1113 fires), stores, and records `D/a`. Expected: the record names `D/b`. Observed:
  `rec->path == "D/a"`; while the inode is cached, `result_path()` 2272–2278 hides it through
  the dentry alias; after `echo 2 > /proc/sys/vm/drop_caches` the stale name is returned.
  A file rename sets neither `paths_stale` nor `top_gen`, so the domain stays fresh.
- **Reproducer:** `tests/review-samedir-rename.c` through `tests/review-3627172-vm.sh`
  (`scan_delay_us=1000000`, the rename 300 ms into the build; the tracepoint
  `moobfs_scan_reread` fires once). Result lines: control `delay=-1 … path_after_drop=b
  exists_b=1 exists_a=0`; defect `delay=300000 … path_after_drop=a exists_b=1 exists_a=0`.
- **Confidence:** reproduced.
- **Note:** the fix of round 1 (journal 0152) recomputes the placement after the registration
  but not the name. The name has to be taken again on every reading (the dentry's name under
  `cur->path`, since the parent check already holds), or a loader that stored a fresher
  reading has to make the older loaders give up.

### R2-3 — A record left partial by a failed update is still "whole" for a later rename or link into another built domain

- **Kind:** defect (ADR-0016's promise "complete or explicitly refused").
- **Severity:** medium. The destination domain answers without the lost attribute, with no
  `lost` flag, no warning and no rebuild, until something else makes it stale. Needs one failed
  update first (a full budget suffices), then a rename or link into another built domain.
- **Where:** `layer/index.c` `index_put()` 448–456 (the old entry is freed at 451 before the new
  one is charged at 457: on `-ENOMEM` the record keeps its other entries), `rec_set_partition()`
  400–419 (an entry that cannot move is dropped), `index_replace()` 1068–1082 (stops at the
  first failure); `rec_whole()` 1879–1885 answers only "is the record's domain built";
  consumers `moobl_index_renamed()` 2023–2025 and `moobl_index_linked()` 2056.
- **Scenario:** domains `da` and `db` built; `da/f` carries `k1` and `k2`; the budget is full.
  `setxattr da/f k1 = new` frees the old `k1` entry and fails to charge the new one:
  `domain_lost(da)` (correct). `rename da/f db/f`: `rec_whole` is true (`da` is still in state
  built; `lost` is not consulted), so the surviving `k2` entry is moved to `db`'s partition and
  nothing marks `db`. `QUERY2 db k1 == new`: expected `f` (the lower holds it); observed: `f`
  missing, and a `MISSING_OK` term on `k1` wrongly matches `f`. The later rebuild of `da` does
  not touch `f`, whose record now belongs to `db`.
- **How to test:** a suite-style step with `index_budget=1M`: build `da` and `db`, write into
  `da` until `moobfs_index_incomplete` fires on a `setxattr` that replaces `k1` of `da/f`, rename
  `da/f` to `db/f`, query `db` for `k1 == new` and compare with `moobfs-index --domain`. Not
  run in this review.
- **Confidence:** certain from the code for the record state and the `rec_whole` decision;
  likely for the visible missing answer (traced, not executed).
- **Note:** a per-record "partial" flag consulted by `rec_whole()` and cleared by
  `index_replace()`, or freeing the whole record on any of the three failures so that the
  consumers adopt from the lower, would close it; `domain_lost` on the source domain stays
  correct either way.

### R2-4 — A failed upper-inode creation leaves the lower object in place behind a valid negative dentry; for `link` the index hooks are skipped

- **Kind:** robustness; for `link`, a stale placement without `domain_lost`.
- **Severity:** medium. One transient `ENOMEM` wedges a name until the dentry is pruned: the
  object exists on the lower, `stat` through the layer gives `ENOENT`, `open(O_CREAT)` gives
  `EEXIST`, `unlink` gives `ENOENT`. The allocation is `SLAB_ACCOUNT`, so a memcg-confined user
  can provoke it in any directory they can write to. After a failed `link`, the lower link
  count is 2 while the index keeps the file homogeneous in its domain (`target_ok()` 563–564
  would now refuse it) until the next rebuild.
- **Where:** `layer/main.c` `moobl_create` 511–526, `moobl_mkdir` 528–545, `moobl_symlink`
  726–743, `moobl_link` 700–724 (`set_nlink` 717 and the hooks 720–721 skipped on error),
  `moobl_instantiate` 478–509, `moobl_get_inode` 145–165 (the failing allocation),
  `moobl_d_revalidate` 288–322 (ref-walk: no "negative upper, positive lower" check; the RCU
  path 282–283 has one and returns `-ECHILD`, so the ref-walk then declares the negative dentry
  valid).
- **Scenario:** `vfs_create` on the lower succeeds (521), `moobl_get_inode` returns `-ENOMEM`
  (156), nothing is undone; the upper dentry stays negative and hashed, its `d_fsdata` lower
  dentry is now positive. ecryptfs, the stated model, unlinks the lower file in `create` when
  its inode creation fails (fs/ecryptfs/inode.c, 6.12).
- **How to test:** `tests/failnth.c` `OP_CREATE` already injects this allocation; add, after a
  faulted call that returned `ENOMEM`, `stat` on the layer and on the lower (must agree) and an
  `open(O_CREAT)` that must not give `EEXIST` while `stat` says `ENOENT`; add an `OP_LINK` with
  the same checks and an oracle comparison of the source domain.
- **Confidence:** certain from the code (the three kernel functions involved were read in the
  6.12 source).

### R2-5 — The build's root path is captured before the `top_gen` snapshot

- **Kind:** concurrency (the class of round 1).
- **Severity:** low. `QUERY2` is unaffected (`scope_path()` strips the domain components); the
  v1 `QUERY` omits every uncached file of that domain until it is rebuilt for another reason.
- **Where:** `layer/index.c` `query2_pin()` 3123 and `domain_ensure_all()` 1618–1631 compute
  the mount-relative path of the domain directory; `domain_ensure()` 1545 snapshots
  `dom->top_gen = ix->top_gen` later, under the lock. A rename of the domain directory (or one
  above it) in between bumps `top_gen` before the snapshot: the domain is built with every
  recorded name under the old prefix and is "fresh".
- **Confidence:** certain for the state; likely for the window (microseconds, not reproduced).

### R2-6 — A failed `record_dentry_path()` in the rename hook keeps the old name in a fresh domain

- **Kind:** robustness (the ADR-0016 pattern missing at one site).
- **Severity:** low.
- **Where:** `layer/index.c` `moobl_index_renamed()` 2024: `record_dentry_path()` can fail (page
  allocation, or `charge()` under a full budget, 1812–1815) and the record keeps the old name;

- **Confidence:** certain from the code.

### R2-7 — `ix->over_budget` is mount-wide and reset by every build

- **Kind:** robustness.
- **Severity:** low, transient.
- **Where:** `layer/index.c` `domain_ensure()` 1543 (reset) and 1577 (read after the scan);
  `charge()` 190–197. A concurrent build of another domain clears the flag between the two, so

- **Confidence:** likely.

### R2-8 — `rec_set_partition()` can leave a record with no entries that nothing frees

- **Kind:** defect (accounting).
- **Severity:** low: one record and its path string per occurrence, `index_inodes` overstated,

- **Where:** `layer/index.c` 400–419 and its callers 2025 and 2089 (`index_put()` 448 is fine).
- **How to test:** `failnth` `OP_CHMOD` on an attributed file (the current `OP_CHMOD_DIR`

- **Confidence:** certain from the code.

### R2-11 — `ix->domains` and `ix->fallback` grow without bound, outside the budget and the shrinker

- **Kind:** robustness (resource).
- **Severity:** low. Needs the right to create domain directories (`domain_depth>=2` with a

### R2-12 — A file whose attribute list exceeds `XATTR_LIST_MAX` is left out of the index silently, against spec §9

- **Kind:** design opinion / documentation.
- **Severity:** low. `docs/spec-query-v2.md` §9 says "a build never answers with part of a
  domain: an ACL or a name that could not be read fails it"; `attrs_read()` 1037–1038 returns
  success on `-ERANGE` from `vfs_listxattr`, so a file with more than 64 KiB of attribute names
  (reachable on btrfs with many non-typed `user.*` names) is answered as having no typed
  attributes. `docs/research-stacked-fs-kernel-rules.md` R-XATTR-3 records the choice; the
  spec and the "never answers with part" sentence do not. Same family as the `getxattr` error
  fixed on a local branch; either fail the build as the spec says, or document the exception.
- **Confidence:** certain from the code; not reproduced.

## Test gaps (priority 5)

T1 of the test review (no permission change ever races a build or an adoption) is the finding
of round 1 and is not repeated. The remaining gaps, each with the mutation of `layer/*.c` that
every marker would miss:

- **T2, medium — the cursor MAC is never the deciding check.** Every refused cursor in
  `vm/suite.sh` 427–438 and `tests/query.c` 381–387 also fails the query hash. A cursor with a
  valid hash and a tampered `ino`, `len` or inline value is never sent. Without the MAC,
  `cursor_decode()` 3060–3066 (long values recovered from the inode's current entry, looked up
  mount-wide with no domain check) would be a cross-domain value-prefix oracle; the MAC is the
  only thing that stops it. Test sketch: dump a valid cursor, flip one byte in each field while
  keeping the hash bytes, expect `ESTALE` each time; one case with `len > 96` and the `ino` of a
  file in another domain.
- **T3, high — `ext_acl(dom)` (`reach_ok()` 548) is never exercised.** `tests/permmatrix.c`
  plants no ACLs; the suite sets ACLs on files only (or on directories with `domain_depth=0`).
  Removing the check passes every marker.
- **T4, high — write-path placement under a private intermediate directory is untested.**
  Every post-mount attribute write in the suite is on a depth-1 file; `vm/suite.sh` 1030–1035
  covers only the rebuild after a directory rename. Removing the intermediate walk of
  `place_dentry_above()` 642–649 passes every marker, and a 0644 file under a 0700 directory
  written after the build would be answered to everyone. Sketch: after `q2-build`, as root
  `mkdir -m 700 da/priv`, create `da/priv/f` 0644, set an attribute through the layer, then
  `rename` and `link` other files into `da/priv`; `QUERY2` as uid 1001 must not list them while
  `fallback_domains` stays 0.
- **T5, medium — `query2_target()` `MAY_EXEC` is never decisive**: the matrix has no
  directory readable without execute, and `db` is 0700 so `open` fails first.
- **T6, medium — `truncated` as a count channel in per-result mode is never asserted** (v1 always

- **T9, medium — `failnth` and `release` query as root only**; no file chmod in `failnth`, so
  the `rec_set_partition` failure path with a homogeneity change is unreached (R2-8).
- **T7, low — `race2`'s forked child verdict is lost** (the line is printed before `waitpid`,
  the suite checks the line, the exit status is `tee`'s); `query … | tee` at `vm/suite.sh`

- **T8, low — directories carrying attributes inside a domain are never compared with the
  lower's decision.**
- **T10, low — hostile lower trees carry no permission adversity** (all 0644 root), and the

  bug.
- **T11, low — `docs/testing.md` overstates the harness**: QEMU exits 0 on both pass and fail

## Sites of priority 1 checked and found correct

Mechanisms: the `ix->loaders` dirty flag (an update to a file being read makes the reading be
done again), `move_gen` in `place_and_lock()` (a placement is recomputed when a rename or a
link completed meanwhile), the VFS locks of each operation (a file's own rename, `setxattr`,
`chmod`, `setfacl` and `link` are serialized by its `i_rwsem`; `vfs_rename` locks non-directory
sources, `vfs_link` and `vfs_unlink` lock the inode), `paths_stale`, `top_gen` and the
`dom->moved` rounds decided under the index lock, the per-domain `fallback` for directory
permission changes, `query_sem` with `drop_gen` and the per-chunk re-find of name nodes, the
keyset cursor with the fallback state in its hash, the `READ_ONCE`/`WRITE_ONCE` pairs on domain
state, and `rec->upper` against eviction.

1. `scan_push_dir()` `inner_ok` and the domain inode used for every child later: a chmod,
   chown or setfacl of an intermediate or of the domain directory sets the fallback (2080–2084),
   fail-safe in the other direction. The directory's own `self.hetero` is the round-1 finding.
2. `scan_run()` `cur->path` for all children: a directory renamed after its push goes to
   `dom->moved` and is scanned again under its new name; the final emptiness of the side list
   is decided under the lock (1552–1557) before `paths_stale` is cleared (1571).
3. `scan_moved()` with `parent == NULL`: later renames of the same directory append newer
   entries and are scanned later, the last name wins.
4. `index_load()` 1111–1113 before the sleep: a later unlink marks the loader dirty and the
   retry sees the lower dentry unhashed; a cross-directory rename marks it dirty and the retry
   sees `d_parent` changed while the rename hook adopted the file. (Same-directory rename:
   R2-2.)
5. `index_load()` 1145–1152 `rec->upper` after a lock drop: `moobl_find_inode()` returns a
   referenced inode (`ilookup5` waits for `I_NEW`), `iput` outside the lock, and
   `moobl_index_inode_evicted()` clears only on pointer equality.
6. `index_adopt()` from `moobl_index_renamed()` and `moobl_index_linked()`: runs under the
   operation's VFS locks, with a placement computed under them; a concurrent scan of the same
   file is a second loader and either reading is whole.
7. `dir_moved_prepare()` before the lock, `dom->state` checked under it (2001): a build that
   finishes in between leaves `paths_stale`; one that starts in between reads the new layout;
   a failed preparation sets `restart` or bumps `top_gen`.
8. `domain_ensure()` 1545 `top_gen` snapshot: a rename at or above the domain during the
   build makes `domain_fresh()` false after it (prefix captured before: R2-5).
9. `domain_ensure()` end of build: the side list, `restart` and the state change are in one
   lock section (1552–1575), so no rename is recorded between the check and the state.
10. `domain_ensure()` failure: `domain_drop()` and the state change under the lock; records
    written by hooks during the build go with it.
11. `domain_release()` from a build: holds the caller's `build` mutex, tries the other's,
    then `query_sem` for writing and the index lock, the order of `domain_ensure()`; from
    reclaim every lock is tried. No caller holds `query_sem` while taking a build mutex
    (`query2_pin()` and `query_repin()` release it first).
12. `moobl_shrink_scan()`: stops without `__GFP_FS`; every index-lock section runs in a NOFS
    scope, so an allocation under the lock cannot re-enter the shrinker or evict an inode.
13. `place_and_lock()` for `moobl_index_set()` and `moobl_index_perm_changed()`: `move_gen`
    covers renames and links of any file; a chmod of the file itself is serialized by its
    `i_rwsem`; a chmod of an intermediate directory sets the fallback; after 8 tries the
    placement may be stale, but only in a domain that `paths_stale` sends to a rebuild.
14. `moobl_index_renamed()` file case: `place_dentry(where, inode)` before the lock, under
    `lock_rename` of the upper parents and the source inode lock; the target dentry still
    carries the new parent before `d_move`; `record_dentry_path(where)` under the lock.
15. `moobl_index_renamed()` RENAME_EXCHANGE: the second call uses `old_dentry` as `where`,
    still at its old place.
16. `moobl_index_renamed()` directory case: `target` computed before the lock cannot change
    (a cross-directory rename of an ancestor needs `s_vfs_rename_mutex`; a same-directory one
    changes no depth).
17. `moobl_index_linked()` then `moobl_index_perm_changed(old_dentry)` in `moobl_link()`:
    both under `vfs_link`'s inode lock; the record ends heterogeneous whichever domain wins.
18. `moobl_index_set()` 1814 `!inode->i_nlink`: serialized with `unlink` by the inode lock
    `vfs_unlink` holds; `domain_live` under the lock, so a store cannot slip between
    `domain_drop` and the state change.
19. `moobl_index_set()` in a domain being built: the record it creates is replaced whole when
    the scan reaches the file, or the file was created after the build began and every
    attribute went through the layer.
20. `moobl_index_remove()` and `moobl_index_drop_inode()`: by inode number, under the lock,
    with `index_touched`.
21. `moobl_index_perm_changed()` on the domain directory itself (`depth == n`): `where_is`
    returns the directory as its own domain, the fallback is set for it; its own attributes
    are placed outside.
22. `moobl_index_inode_cached()` and `index_replace()` freeing a record: whichever runs last
    sets `rec->upper`.
23. `moobl_index_inode_evicted()` from `evict_inode`: takes the index lock; no index-lock
    section calls `iput`, `dput` of the last reference happens after the unlock in
    `query_run()` and `index_load()`.
24. `result_path()` under the read lock: `d_find_alias()` on `rec->upper` is safe because the
    eviction hook needs the write lock before the inode memory is freed; the alias is held
    until after the unlock.
25. `query_run()` per chunk: `tn[]`, `nm` and the resume key are re-found under the read lock
    after every unlock; `query_repin()` rebuilds or fails with `EAGAIN` (v1) when the domain
    was taken down; `drop_gen` is read while `query_sem` is held.
26. `query2_exec()` `sc.check` and the query hash: a fallback that begins during a query is
    the TOCTOU contract; a cursor issued before it is refused by the hash.
27. `cursor_decode()` long-value recovery: under the read lock with the domain pinned; a
    changed value either fails the prefix check or gives a harmless resume key.
28. `leap_collect()` `resume->lead` across chunks: an index into the request's own terms;
    name nodes are re-found per chunk.
29. `query2_target()` depth and domain of the descriptor: a rename to another depth is refused
    (`EXDEV`); a rename at the same depth bumps `top_gen` and the pin rebuilds.
30. `moobl_rename_crosses_domain()` before `lock_rename` of the lower: a cross-directory
    rename of an ancestor needs the upper `s_vfs_rename_mutex`, which the VFS holds for this
    rename when the parents differ; same-directory renames change no depth or domain.
31. `moobl_unlink()` with a remaining link (`nlink` 2 → 1): the record stays heterogeneous
    and its stale name is used only in check mode, where it leads to omission (documented
    fail-safe).
32. `moobl_rename()` replacing a target: `moobl_index_drop_inode` reads the lower's link
    count under `lock_rename`.
33. Counters: `hetero_count` in `rec_set_partition()` and `inode_rec_put_if_empty()`;
    `entries`, `used`, `inode_count` and the name nodes balanced across `index_put()`,
    `entry_free()`, `rec_set_partition()`'s failure path and `domain_drop()` (R2-8 is the one
    record that outlives its entries).
34. `where_is()` under `rename_lock`, no allocation, `lockref_get_not_dead` on the domain
    dentry; repeated on a sequence change. (Its depth limit: R2-1.)
35. `main.c` hook order: every hook runs after the lower operation succeeded and under that
    operation's VFS locks (`moobl_xattr_set` 970–979, `moobl_unlink` 571, `moobl_rmdir` 597,
    `moobl_rename` 669–676 before `d_move`, `moobl_link` 720–722, `moobl_set_acl` 826,
    `moobl_setattr` 1047); a build reading the same file is not serialized with them, which is
    what the loaders are for.
36. `moobl_qbuf_get()`/`moobl_qbuf_put()`: a second query on the same descriptor gets its own
    buffer; results are copied before the buffer is returned.
37. `moobl_index_mount()`, `moobl_index_init()`, `moobl_index_destroy()` and `moobl_kill_sb()`
    order: eviction hooks run on an initialized index; the shrinker is freed first.

## Priority 3 — VFS operations

Compared with overlayfs and ecryptfs at v6.12 (`fs/overlayfs/{file,inode,super,dir}.c`,
`fs/ecryptfs/{file,inode}.c`, `fs/backing-file.c`, `fs/stat.c`, `fs/sync.c`, `mm/fadvise.c`,
`fs/namei.c`, `fs/stack.c` fetched). What the layer does with each operation:

| Operation | Layer | Note |
|---|---|---|
| open (regular) | `backing_file_open` with the mounter's credentials, `FMODE_BACKING`, user path the upper's | as overlayfs |
| open (directory) | `dentry_open` of the lower with the mounter's credentials; caller's `O_NOATIME` not passed | ecryptfs-like |
| fifo, socket, device | `init_special_inode` on the upper: a FIFO or socket is a separate endpoint through the layer; devices refused by `SB_I_NODEV` | as both references; the comment at `main.c` 137–139 says "opening them is refused", which is true for devices only (V9) |
| mmap | `backing_file_mmap`: pages live in the lower mapping, `/proc/pid/maps` shows the layer path | as overlayfs |
| read_iter, write_iter, splice | `backing_file_*`; writes under the upper `inode_lock` with `file_remove_privs` (doubled by the helper, harmless) and the writer's fsuid (F4) | as overlayfs |
| copy_file_range, remap_file_range, fallocate | forwarded under the writer's credentials, upper locked, privileges dropped; `EXDEV` across superblocks | known (0079) |
| fadvise, readahead(2), cachestat(2) | **no `.fadvise`: `generic_fadvise` acts on the empty upper mapping** (V1) | overlayfs forwards |
| sync_file_range(2) | acts on the empty upper mapping, returns 0 (V2) | same gap in overlayfs; no hook exists |
| fsync | `vfs_fsync_range` on the real file under the mounter's credentials, also for directories | fine |
| flush | the real file's `flush` with the caller's credentials; none of ext4, btrfs, XFS has one | known (#16) |
| fiemap | direct lower `->fiemap` under the mounter's credentials | known (#16) |
| `FS_IOC_*FLAGS`, `FS_IOC_FS*XATTR` | `fileattr_get/set` on the lower with the caller's credentials; `FS_CASEFOLD_FL` refused | fine |
| other ioctls on files | no `.unlocked_ioctl`: `ENOTTY`; directories: the query ioctls and `compat_ptr_ioctl` | fine |
| O_TMPFILE | no `.tmpfile`: `EOPNOTSUPP` | known (0075) |
| mknod | no `.mknod`: `EPERM` | known (0012, 0075) |
| statx | `vfs_getattr_nosec` on the lower, `generic_fillattr` on the upper, then `blocks`, `blksize`, `btime` and four attribute bits; **`STATX_DIOALIGN`, `STATX_WRITE_ATOMIC`, subvolume id, `ENCRYPTED`/`VERITY`/`DAX` dropped** (V3) | ecryptfs-grade; overlayfs starts from the lower's kstat |
| d_revalidate | RCU path refuses an unhashed lower, positivity or inode mismatch, `nlink` 0; ref-walk path checks none of these (V4, same as M5) | both references behave like the ref-walk path |
| d_weak_revalidate, d_hash, d_compare | none; casefold refused | fine |
| export (NFS) | no `s_export_op`: nfsd `EINVAL`, `name_to_handle_at` `EOPNOTSUPP`, fanotify FID marks on the mount `EOPNOTSUPP` | clean refusal |
| sync_fs | `sync_filesystem` on the lower under its `s_umount`, upper `SB_I_SKIP_SYNC` | as overlayfs |
| freeze | no `freeze_fs`: `FIFREEZE` `EOPNOTSUPP`; a frozen lower blocks layer writes through `mnt_want_write` | fine |
| statfs | lower's with `f_type` rewritten; `f_fsid` and `f_namelen` the lower's | overlayfs rewrites `f_namelen` |
| remount | only unchanged options accepted; ro/rw the VFS's | known (0106, 0118) |
| drop_inode | default: unreferenced upper inodes stay cached and pin the lower inode, so a file deleted behind the layer keeps its blocks until eviction (V5) | overlayfs uses `generic_delete_inode` |
| permission, idmap | `inode_permission` on the lower with the caller's credentials; `FS_ALLOW_IDMAP` and `FS_USERNS_MOUNT` unset; idmapped lower refused | known (F12) |
| ACLs, xattrs | delegated; `ACL_DONT_CACHE`; `security.*` read with the mounter's credentials | known |
| lock, flock, lease | none: locks and leases live on the upper inode, invisible to lower-side users | as overlayfs |
| readdir, llseek | `iterate_dir` on the real file under the mounter's credentials with the upper context; seeks under the upper lock | as overlayfs |
| readlink | `vfs_get_link` on the lower, `-ECHILD` in RCU | fine |
| rename flags | forwarded unchanged: **`RENAME_WHITEOUT` creates a device node through a layer that refuses `mknod`** (V6); `RENAME_EXCHANGE` handled by the index | overlayfs and ecryptfs refuse unknown flags |
| link, symlink | `EPERM` with `nolinks` | known |
| F_SETFL | flags copied to the real file at open only: **`O_DIRECT`, `O_NOATIME`, `O_NONBLOCK` set later never reach the lower** (V7; `O_APPEND` is the known case) | overlayfs re-applies them (`ovl_change_flags`) |
| inotify, fanotify | events on the upper from the VFS helpers; the lower also sees the real-file calls | fine |

| swapfile | no `swap_activate`: `swapon` `EINVAL` | clean refusal |
| `moobl_rename` attribute copy | `fsstack_copy_attr_all` copies the whole lower `i_flags` word (and `nlink`) on four inodes, reintroducing on one path what journal 0079 masked elsewhere (V8) | overlayfs never copies `i_flags` |

Findings of this priority (all low; V4 is M5 of priority 4 seen from the other side):

- **V1, low (certain) — `posix_fadvise`, `readahead(2)` and `cachestat(2)` are silent no-ops**
  (`layer/main.c` 1477–1491, no `.fadvise`; `moobl_aops` 101–104). Advice such as
  `POSIX_FADV_DONTNEED` never reaches the only page cache that exists. Test: read a 64 MiB
  file through the layer, `fincore` the lower file, `posix_fadvise(DONTNEED)` on the layer
  descriptor, `fincore` again (still resident; through the lower it is evicted). Fix shape:
  `.fadvise` forwarding `vfs_fadvise` to the real file, as `ovl_fadvise`.
- **V2, low (certain) — `sync_file_range(2)` succeeds without writing anything**; the same
  in overlayfs, since no hook exists; worth a line in the README beside `noatime`.
- **V3, low (certain) — `statx` drops lower-provided fields** (`layer/main.c` 989–1012):
  `STATX_DIOALIGN`, `STATX_WRITE_ATOMIC`, `STATX_SUBVOL` and the `ENCRYPTED`, `VERITY` and
  `DAX` attributes; programs sizing `O_DIRECT` buffers fall back to "unknown". Fix shape:
  start from the lower's kstat and overwrite `dev`, `ino`, `nlink`, as overlayfs does.
- **V4, low (certain) — the ref-walk `d_revalidate` checks less than the RCU path**
  (`layer/main.c` 266–322): a lower file removed behind the layer passes ref-walk and fails
  RCU-walk, so the answer depends on the walk mode; also the state R2-4 leaves behind.
- **V5, low (certain for the mechanism) — the default `drop_inode` keeps unreferenced upper
  inodes cached, pinning the lower inode**; `df` returns the space of a file deleted behind
  the layer only after eviction. Switching to `generic_delete_inode` would change when the
  index learns of evictions: a design decision, not a one-liner.
- **V6, low (certain for the forwarding) — `RENAME_WHITEOUT` is forwarded** (`layer/main.c`
  602–697): as root, `renameat2(…, RENAME_WHITEOUT)` creates a `c 0 0` node on the lower that
  the layer shows as a special inode. Fix shape: refuse flags other than `RENAME_NOREPLACE`
  and `RENAME_EXCHANGE` with `EINVAL`, as both references do.
- **V7, low (certain for the mechanism) — `F_SETFL` changes other than `O_APPEND` never reach
  the lower file** (`layer/main.c` 1250–1266, 1280–1311): `O_DIRECT` set after open silently
  degrades to buffered I/O on the lower; `O_NOATIME` does not stop the lower's atime. Fix
  shape: re-apply the differing bits to the real file on each operation (`ovl_change_flags`),
  or refuse them in `.check_flags`.
- **V8, low (certain for the copy; the consequence speculative) — `moobl_rename` copies the
  whole lower `i_flags` word with `fsstack_copy_attr_all`** (`layer/main.c` 674–680), against
  the mask of journal 0079; replace with `moobl_copy_attr` plus `set_nlink`.
- **V9, low — documentation:** a FIFO or socket in the lower is a separate endpoint through
  the layer; only devices are refused.

*Note, 2026-10-28:* V1, V3, V5 and V7 are fixed in journal 0224 (issue 115): `.fadvise` forwards
to the lower file (and with it `readahead(2)`), `statx` copies the lower's fields, an inode whose
lower file has no link left is dropped, and `O_NOATIME` joins the `F_SETFL` bits synchronized
since journal 0149. `cachestat(2)` of V1 stays a limitation, as in overlayfs.

Consistent with the references, no finding: backing files and `FMODE_BACKING`; `O_DIRECT` at
open (`FMODE_CAN_ODIRECT` from `direct_IO`); lease breaking and `i_writecount` on the lower
through `do_dentry_open`; clean refusals of export, `FIFREEZE`, `swapon` and unknown ioctls;
`FS_IOC32_*` remapped generically; the readdir and llseek lock order (upper then lower);
`permission()` with `MAY_NOT_BLOCK`; the security hooks on the lower preceded by the same
check on the upper; `S_NOSEC` on the upper cleared where it must be; `sync_fs`. Claims resting
on 6.12 behaviour not fetched verbatim: `do_renameat2` requiring `CAP_MKNOD` for
`RENAME_WHITEOUT`; the contents of `OVL_SETFL_MASK`; `__vfs_setxattr_noperm` clearing
`S_NOSEC` on `security.*` writes; the `quotactl` errno without `s_qcop`.

## Priority 4 — a maintainer's reading

References read at v6.12 (`Documentation/filesystems/` locking, vfs, porting,
directory-locking and overlayfs; `Documentation/userspace-api/ioctl/ioctl-number.rst`;
`fs/inode.c`, `fs/namei.c`, `fs/xattr.c`, `fs/dcache.c`, `fs/backing-file.c`,
`fs/overlayfs/{inode,super,file,params}.c`, `fs/ecryptfs/inode.c`, `include/linux/fs.h`,
`include/linux/backing-file.h` at v6.12 and v6.12.112, `mm/shrinker.c`). Four claims rest on
files not fetched (`gfp_types.h`, `core-api/memory-allocation.rst`, `fs/super.c`,
`fsnotify.h`, `mm/mmap.c`) and are marked unverified.

Defects, robustness and security:

- **M1, medium (certain for the code; the memcg effect unverified) — kernel memory sized by an
  unprivileged user, without accounting, and up to about 1 MiB kept alive per open
  descriptor.** `layer/main.c` 1198–1228 and 1275 keep the query buffer (`limit` × 272 bytes,
  up to 4096) with the open file; every index, scan and query allocation is plain
  `GFP_KERNEL` with no `__GFP_ACCOUNT`; the budget goes up to 4 GiB. The fair-shares part of
  F2 covers the budget; this is about what a cgroup limit cannot see.
- **M2, medium (certain) — a mount-wide `rw_semaphore` is taken for writing on every inode
  instantiation and every eviction of the superblock** (`layer/main.c` 162 and 193,
  `layer/index.c` 2114–2142), even when no record exists. The raw `rec->upper` pointer is what
  forces the lock into `evict_inode`; keeping that state in the inode (or looking the inode up
  by `ilookup5` when a path is needed) would take it out of the reclaim path.
- **M3, medium (certain for the cost; acceptance is a judgement) — an unprivileged `QUERY2`
  makes the kernel walk a whole subtree with the mounter's credentials** (`layer/index.c`
  3109–3142, 1495–1601), again after any directory rename in the domain (1994–1999), and may
  evict other users' built domains to make room (1577–1586). Bounded by `index_budget` in
  memory, not in CPU or I/O; the kernel has no precedent for an unprivileged, unbounded tree
  walk on request. Overlaps ADR-0011 non-promise 5 only for the budget.
- **M4, low to medium (certain) — `->lookup` returns `EXDEV` (btrfs subvolume) and
  `EOPNOTSUPP` (casefolded directory) for names `readdir` lists, and warns with
  `pr_warn_ratelimited` from a user-reachable path** (`layer/main.c` 375–410). `vfs.rst`
  says `lookup` fails only on a real error; overlayfs refuses the configuration at mount
  (`sb_has_encoding`) and handles several devices with `xino`.
- **M5, low (certain) — the two halves of `d_revalidate` disagree**: the RCU path refuses an
  unhashed lower dentry, the ref-walk path never checks `d_unhashed` and its `i_nlink` test is
  dead because `moobl_copy_attr()` does not copy the link count (`layer/main.c` 266–322),
  contrary to the comment at 256–264. Reachable only through changes behind the layer
  (non-promise 2), and it is the other half of R2-4.
- **M6, low (certain) — the ioctl magic `'M'` is registered in-tree by four users, one of
  them "all"** (`ioctl-number.rst`: soundcard.h, mtd-abi.h 01–16, megaraid 01–03, fsl-diu-fb
  00–0F); `struct moob_query_term` has one byte of implicit tail padding. Known to the
  project (`docs/research-stacked-fs-kernel-rules.md` line 321), still unfixed.
- **M7, low (certain for the inconsistency) — `capable(CAP_SYS_ADMIN)` and
  `ns_capable_noaudit(&init_user_ns, CAP_SYS_ADMIN)` gate related things** (`layer/index.c`
  2904 and 3348); `CAP_DAC_READ_SEARCH` is the narrower fit for "see what DAC would show".
- **M8, low (certain), one line each:** `backing_file_open(file, …)` builds only against the
  stable-backported signature (`const struct file *` in v6.12.112 and the Debian 6.12.111
  headers; `const struct path *` at the v6.12 tag), with no guard; `vfs_getattr_nosec()`
  always, while ecryptfs honours `AT_GETATTR_NOSEC`; `moobl_flush()` runs with the caller's
  credentials unlike `ovl_flush()`; `fileattr_set` without the lower `i_rwsem` (parity with
  ecryptfs and overlayfs); `SB_I_NOEXEC` not mentioned in `docs/when-not-to-use.md`;
  `scan_delay_us` as a module parameter in production code; `pr_warn_ratelimited` on
  user-driven paths.

*Note, 2026-10-28:* M4 and M8 are fixed in journal 0221 (`EREMOTE` for a casefolded directory,
`ESTALE` if casefolded behind the layer, `EXDEV` kept for a subvolume, once-only logs; the M8
items fixed or answered one by one there) and M6 and M7 in journal 0222 (ADR-0026: the magic
kept, the padding byte named and checked, one privilege test), closing issue 119. M2 (issue 117)
is fixed in journal 0223 for inodes without an index record; an inode with a record still takes
the lock, and removing `rec->upper` stays a proposal there.

Design opinions, kept apart from defects:

- **D1, high as a review objection — the kernel validates the values of `user.*`
  attributes** (`layer/main.c` 894–943). The VFS treats `user.*` as opaque bytes owned by the
  user (`xattr_permission()` gates only by file type and the sticky bit); the writer already
  has the same validator in `common/attr.c`.
- **D2, high as a review objection — the homogeneity rule is a second permission model,
  evaluated from a snapshot** (`layer/index.c` 506–666, 1263–1301), bypassing
  `inode_permission()` per result unless an LSM-label probe or a chmod flips the fallback.
  `overlayfs.rst`'s model is two real permission checks at access time; F9 was exactly a
  divergence between the rule and `acl_permission_check()`, and R2-1 is another.
- **D3, high as a review outcome — whether this belongs in the kernel.** Against: the layer is
  a pure pass-through (no data transformation, unlike ecryptfs, overlayfs or FUSE
  passthrough); the index is a volatile cache rebuilt by a tree walk, which is what
  `updatedb` and `tracker` do in user space; `setxattr` raises `fsnotify` `FS_ATTRIB`
  (unverified at v6.12), so a user-space indexer can be exact; the repository already has a
  SQLite front end. For: the index is updated atomically with the write under `i_rwsem`, there
  is no daemon, and the lower tree stays plain. The likely maintainer answer is to ship the
  user-space index and keep the module as the experiment, or to propose a `fanotify`
  extension carrying attribute values instead of a filesystem. The project's own position is
  ADR-0007 and `docs/when-not-to-use.md`; this review records the objection, not a decision.
- **D4, low — the `index_idle` floor lets a hot mount opt out of reclaim**; the rbtree, the
  xarray, the siphash cursor and the tracepoints are fine as they are.

Passes unchanged, so that nothing is "fixed" by mistake: `iget5_locked` keyed by the lower
inode pointer with `i_ino` parity, as ecryptfs; `d_fsdata` freed under RCU; `lock_parent` and
`lock_rename` with `IS_ERR` handling; `mnt_want_write` around every lower change;
`CAP_SYS_RESOURCE` lowered in the mounter credentials; `ATTR_MODE` stripped with
`ATTR_KILL_S*ID`; `backing_file_*` with `inode_lock` across writes; permission delegated to the
